# cafe-compiler

C 風の小さな言語を **Wii U TCPGecko の Cafe Code（cafe codetype）** に変換するコンパイラと、その逆を行う逆コンパイラです。

```c
if (*(u32*)0x10000000 == 1) {
    *(u16*)0x10000004 = 0x63;
}
```

```
03020000 10000000
00000001 00000000
00010000 10000004
00000063 00000000
D0000000 DEADCAFE
```

- 依存パッケージなし（Node.js 18 以上のみ）
- エンコードは [tcpgecko-codetypes-documentation](https://github.com/BullyWiiPlaza/tcpgecko-codetypes-documentation)（TCP Gecko 2.53）に準拠。ドキュメントで曖昧な点はコードハンドラの逆アセンブルで確認しました（[曖昧な点](#ドキュメントの曖昧な点と本実装の解釈)）
- エラーは `ファイル:行:列` と該当行、ヒントを日本語で表示します

## 使い方

```sh
./compile input.cafe -o out.txt          # コンパイル
./compile input.cafe --listing           # 各行に元のソースをコメントで付ける（確認用）
./decompile codes.txt -o out.cafe        # 逆コンパイル
npm test                                 # テスト
```

`npm link` すると `compile` / `decompile` コマンドとして使えます。`-o` を省略すると標準出力に出し、入力に `-` を指定すると標準入力から読みます。

エラーの例:

```
bad.cafe:2:24: エラー: 値 256 は u8 (8bit) に収まりません
   2 |     *(u8*)0x10000000 = 0x100;
     |                        ^
```

## 言語仕様

### 基本

- 文は `;` で終わります。コメントは `//` と `/* */` です。
- 数値は 10 進数、`0x` で始まる 16 進数、`0b` で始まる 2 進数、浮動小数点数（`1.5`、`1e-3`、`2.0f`）が書けます。`_` で桁を区切れます。
- 定数は `const NAME = 式;` で宣言します。定数式では `+ - * / % & | ^ << >> ~` が使えます。
- メモリは `*(型*)アドレス` で参照します。型は `u8 s8 u16 s16 u32 s32 f32` です。
  - `s8`/`s16`/`s32` に書いた負の値は 2 の補数に変換されます（`*(s16*)A = -1` → `FFFF`）。
  - `f32` に書いた値は IEEE754 単精度のビット列に変換されます（`1.5` → `3FC00000`）。

### 文とコードタイプの対応

| 構文 | コードタイプ |
|---|---|
| `*(u8/u16/u32*)A = 値;` | RAM Writes [00] |
| `write(A, "文字列");` / `write(A, [0x01, 0x02]);` | String Writes [01] |
| `skip_write(*(型*)A, 値, 回数, 間隔 [, 増分]);` | Skip Writes [02] |
| `memfill(A, 値, 長さ);` | Memory Fill [20] |
| `memcpy(コピー先, コピー元, 長さ);` | Memory Copy [21] |
| `corrupt(開始, 終了, 検索値, 置換値);` | Corruptor [F0] |
| `if (*(型*)A == 値)` ほか `!= > < >= <=` | If [03]〜[08] |
| `if ((*(型*)A & M) == M)` | Conditional AND [09] |
| `if ((*(型*)A & M) != 0)` / `if (*(型*)A & M)` | Conditional OR [0A] |
| `if (between(*(型*)A, 下限, 上限))` | If Value Between [0B] |
| `timer (フレーム数) { ... }` | Add Time-Dependence [0C] … [D2] |
| `reset_timer(*(u16*)A == 値);` | Reset Timer [0D] |
| `if (button(ボタン [, コントローラ [, ポート]]))` | Input Conditional [0E] |
| `else` / `!条件` | Negate Conditional [0F] |
| `loop (回数) { ... }` | Loop [80] … [D1] |
| `loop (rN) { ... }` | Loop Indexed [81] … [D1] |
| `break;` | Break Loop [82] |
| `rN = *(u8/u16/u32*)A;` / `*(型*)A = rN;` | Load / Store Integer [10] / [11] |
| `fN = *(f32*)A;` / `*(f32*)A = fN;` | Load / Store Float [12] / [13] |
| `rN += rM;` `rN *= 3;` `rN = 5;` など | Integer Operations [14] |
| `fN += fM;` `fN *= 2.0;` `fN = 1.5;` など | Float Operations [15] |
| `fN = float(rM);` / `rN = int(fM);` | [14] 演算 8 / [15] 演算 8 |
| `pointer *(u32*)A [in (開始, 終了)] { ... }` | Load Pointer [30] … [D0] |
| `ptr = *(u32*)(ptr + K);` | Pointer-in-pointer [30] (30100000) |
| `ptr += K;` / `ptr += rN + K;` | Add Offset To Pointer [31] / [32] |
| `ptr -= K;` / `ptr -= rN + K;` | Subtract Offset From Pointer [33] / [34] |
| `asm { 命令ワード, ... }` | Execute ASM [C0]（末尾が `blr` / `bctr` / `b` でなければ `blr` を自動で付けます） |
| `call(A);` / `syscall(番号);` | System- And Procedure Calls [C1] |
| `hook_lr(A) { ... }` / `hook_ctr(A) { ... }` / `asm_write(A) { ... }` | [C2] / [C3] / [C4] |
| `message("文字列" [, 0xRRGGBB]);` / `message(ptr [, 色]);` | Display Message [E0] / [E1] |
| `clear_message();` | Clear Message [E2] |
| `raw(0x上位, 0x下位);` | 1 行をそのまま出力 |
| `pointer_range(開始, 終了);` | 以降の `pointer` の既定範囲を変更（コードは出力しません） |

### 条件

- `&&` で条件を並べられます（条件コードを連続して出力します）。`||` はコードハンドラで表現できないためエラーです。
- 比較の片側は `*(型*)アドレス`、もう片側は定数でなければなりません（メモリ同士やレジスタの比較を行うコードタイプはありません）。
- `else` / `else if` は Negate [0F] で実現します。`!(a == b)` は逆の比較 `a != b` に置き換え、それ以外の `!` は 0F を付けます。
- 終端コード: 一番外側の条件ブロックは `D0000000 DEADCAFE` で、入れ子の内側の条件ブロックは `D2000000 CAFEBABE` で閉じます。内側の条件がブロックの最後にあるときは、外側の D0 がまとめて閉じるので D2 は出しません。

```c
if (*(u16*)0x10000000 != 0 && (*(u32*)0x10000004 & 0x40) == 0x40) {
    if (*(u8*)0x10000008 >= 3) {
        *(u8*)0x10000008 = 3;
    }
    *(u8*)0x10000009 = 1;
}
```

```
04010000 10000000
00000000 00000000
09020000 10000004
00000040 00000000
07000000 10000008
00000003 00000000
00000000 10000008
00000003 00000000
D2000000 CAFEBABE
00000000 10000009
00000001 00000000
D0000000 DEADCAFE
```

### ボタン定数

`button()` では以下の定数が使えます。値はドキュメントの Input Conditional [0E] の表と同じです。

- コントローラ: `GAMEPAD`(0) `WIIMOTE`(1) `NUNCHUK`(2) `CLASSIC` / `PRO`(3)
- ボタン: `VPAD_*`（GamePad）、`WPAD_*`（WiiMote）、`NUNCHUK_*`、`CLASSIC_*`、`PRO_*`。
  ボタン名は `A B X Y ONE TWO LEFT RIGHT UP DOWN Z C ZL ZR L R PLUS MINUS HOME SYNC STICK_L STICK_R TV LSTICK_UP …` です。`|` で組み合わせられます（例: `button(VPAD_ZL | VPAD_R)`）。

### ポインタ

```c
pointer *(u32*)0x10A0B0C0 in (0x10000000, 0x40000000) {
    *(u32*)(ptr + 0x20) = 99;          // 00120020 00000063
    ptr = *(u32*)(ptr + 0x10);         // 30100000 00000010 (ポインタの中のポインタ)
    ptr += 8;                          // 31000000 00000008
}
// 1 行で書ける連鎖ポインタ（自動で pointer ブロックに展開します）
*(u32*)(*(u32*)(*(u32*)0x10A0B0C0 + 0x10) + 0x30) = 5;
```

- `in (開始, 終了)` は RANGE_ST / RANGE_EN です。省略すると `0x10000000`〜`0x50000000` を使います（`pointer_range()` で変更できます）。
- `ptr = ...` で範囲を省略すると、そのブロックの範囲を引き継ぎます。
- ポインタは D0 でしか解放されません。このため外側の条件ブロックの途中や `loop` / `timer` の中の条件の内側には置けず、置いた場合はエラーになります。

### レジスタ

整数レジスタ `r0`〜`r7` と float レジスタ `f0`〜`f7` があります。コード上のレジスタ番号欄は 1 バイトなので `r255` / `f255` まで書けますが、8 以上は警告を出します（[曖昧な点](#ドキュメントの曖昧な点と本実装の解釈) の 14）。

```c
r0 = *(u32*)0x10000000;     // 10020000 10000000
r1 = r0 * 2 + r3;           // 左から順に計算: r1 = 0; r1 += r0; r1 *= 2; r1 += r3
*(u32*)0x10000004 = r1;     // 11020001 10000004
f0 = float(r0);             // 14080000 00000000
```

- 右辺は「値（定数・レジスタ・メモリ読み込み・変換）」に「演算子 定数/レジスタ」を左から繋げた形だけを書けます。式は通常の優先順位で解析し、左から 1 つずつ計算できない形（例: `r3 + r0 * 2`）はエラーになります。
- 整数では `+ - * / & | ^`、float では `+ - * /` が使えます。
- メモリへの直接の `+=` はできません（レジスタを経由してください）。

## 逆コンパイラ

```sh
./decompile codes.txt -o out.cafe
```

```
$ ./decompile examples/01_basic.txt
if (*(u32*)0x10000000 == 1) {
    *(u16*)0x10000004 = 0x63;
}
...
```

- 入力は 1 行に `XXXXXXXX YYYYYYYY`（区切りの空白は省略可）。`#` と `//` 以降はコメントとして無視します。形式が不正な行はエラーになります。
- 条件・タイマー・ポインタ・ループはブロックに戻します。D2 は直近の条件を 1 段、D0 は直近のループの内側の条件とポインタをすべて、D1 はループを閉じます。
- `asm` / `hook_lr` / `hook_ctr` / `asm_write` は 1 行 1 命令で出力し、PowerPC の逆アセンブル結果をコメントで付けます。

```c
asm {
    0x60000000,  // nop
    0x9421FFE0,  // stwu r1, -0x20(r1)
    0x3D200316,  // lis r9, 0x316
    ...
    0x7C0803A6,  // mtlr r0
    0x4E800420   // bctr
}
```

- 入れ子の条件は、else が無く本体がその条件だけなら `&&` にまとめます。`else` の本体が `if` だけなら `else if` にします。
- 条件の直後にある 0F は、比較 [03]〜[08] なら「空の then + else」、[09]〜[0B]・[0E] なら否定（`!button(...)` など）として表します。
- 各コードは一度解読してから再エンコードし、元の行と完全に一致するときだけ構文に戻します。不明なコードタイプ、未使用ビットが立っているコード、文脈に合わないコード（ポインタ未読込でのポインタ版、ループ外の 82、対応しない D0/D1/D2、入れ子ループ など）は失敗させずに `raw(0x..., 0x...);  // 理由` として出力します。C0 や String Write のように行数が決まっているコードは、データ行も含めてまとめて `raw` にします（データ行を別のコードと読み違えません）。`raw` は同じ行をそのまま出力するため、再コンパイルしても内容は変わりません。
- 出力したソースは内部で再コンパイルし、元のコードと異なれば警告します。コンパイラが出力したコードは必ず同じコードに戻ります（テストで確認しています）。手書きのコードでは次の場合に違いが出ます（意味は同じです）:
  - 下位ワードが `00000000` の終端（ドキュメントでは許されています）は `DEADCAFE` などに正規化されます。
  - 最外の条件を D2 で閉じている場合は D0 になります。終端の無いブロックには終端を補います。

## ドキュメントの曖昧な点と本実装の解釈

ドキュメントだけでは決まらない点は、TCPGecko 付属のコードハンドラ（`codehandler.bin` と `tcpgecko/src/tcpgecko/code_handler.h`）を逆アセンブルして確認しました。

1. **D0 と D2 の使い分け**: ドキュメントは条件の例をすべて D0 で閉じています。ハンドラでは D0 が「全段の条件とポインタをリセット」、D2 が「条件を 1 段だけ閉じる」ため、入れ子の内側は D2 で閉じないと外側の条件が後続のコードに効かなくなります。本実装は最外を D0、内側を D2 で閉じます。
2. **float → int 変換 [15] 演算 8**: ドキュメントの書式は `150O0R0R` ですが、ハンドラは float レジスタ R を変換して整数レジスタ **S** に格納します。`rS = int(fR)` → `15080R0S` とし、同じ番号同士ならドキュメントの書式と一致します。
3. **int → float 変換 [14] 演算 8**: 説明文「Integer register S = Converted float register R」は向きが逆に読めますが、ハンドラは整数レジスタ R を変換して float レジスタ S に格納します。`fS = float(rR)` → `14080R0S` です。
4. **比較の符号**: ハンドラは 8/16bit をゼロ拡張して読み、`cmpw`（符号付き）で比較します。このため 32bit の大小比較は符号付き、8/16bit は実質符号なしです。該当する場合は警告を出します。f32 は整数として比較されるため、大小比較はエラーにしています。
5. **If Value Between [0B]**: 古いハンドラ（`codehandler.bin`）は下限・上限を含む符号なし比較、新しいハンドラ（`code_handler.h`）は両端を含まない比較です。境界値に頼らない範囲を指定してください。
6. **[09] AND / [0A] OR**: ハンドラの実装どおり、[09] は `(値 & V) == V`、[0A] は `(値 & V) != 0` として扱います。
7. **ポインタ書き込み [00] のオフセット**: `001SKKKK` の KKKK は 16bit 符号なしです（0〜0xFFFF）。それ以外の範囲は `ptr += ...` でずらしてください。他のポインタ版コードの KKKKKKKK は 32bit で、負のオフセット（`ptr - 8`）も使えます。
8. **Loop Terminator の値**: ドキュメントには `DEADCODE` と `DEADC0DE` の両方がありますが、16 進数として正しい `DEADC0DE` を使います。
9. **ループの入れ子**: ハンドラのループカウンタは 1 つだけなので、`loop` の入れ子はエラーにしています。
10. **Execute ASM [C0]**: 書式欄は `C000NNNN 4E800020` ですが、サンプルのとおり 1 行目の下位ワードが最初の命令です。ドキュメントは「最後は LR へ分岐（blr）」としていますが、`mtlr` で LR を戻して `bctr` で別の関数へ飛ぶコードもよく使われます。そこで `asm {}` の最後が戻ってこない無条件分岐（`blr` / `bctr` / `b`）ならそのまま使い、それ以外なら `blr` を付け加えます。奇数で余った場所は `00000000` で埋めます。
11. **Negate [0F] と `&&`**: 0F は直近の 1 段しか反転しないため、`&&` を含む条件に `else` は付けられません（エラー）。
12. **Time-Dependence [0C]**: ドキュメントどおり、指定フレーム数が経過するまで中身を実行し、D2 で閉じます。
13. **Memory Fill / Copy / Corruptor / Message**: ドキュメントのとおり 1 回だけ実行されます。条件が偽になった後や、コードを送り直した後は再び実行されます。
14. **レジスタ番号 8 以上**: ドキュメントは「レジスタは 0〜7 の 8 本」としていますが、番号欄（`1002000R` の R、`140O0R0S` の R・S など）はハンドラが 1 バイトとして読みます。実際に `10120019 ...` のように 8 以上を使うコードも出回っています。ハンドラごとの扱いは次のとおりです。
    - 新しいハンドラ（`code_handler.h`）は番号の下位 3bit だけを使います。`r8` は `r0`、`r25` は `r1` と同じになります。
    - 古いハンドラ（`codehandler.bin`）は `0x10014F00 + 番号×4` をそのまま使います。整数の `r8`〜`r15` は別の領域になり、`r16` 以上は float レジスタ（`0x10014F40`〜）と重なります。

    本実装はエラーにせず、番号をそのまま出力して警告を出します。逆コンパイラも `r25` のように構文に戻します。
